25. **PDF pipeline determinism (D42, implemented 2026-08-09).** The brand-guide PDF was host-dependent: Lexend 600 rendered as synthetic bold, and the guide's seven symbol glyphs (Δ → ↔ ≈ ≤ ≥ ′) fell through to whatever fonts the build host supplied (Segoe UI / Segoe UI Semibold / Arial Bold on Windows). Three stacked causes, each isolated by controlled headless-Chrome print experiments: **(a) single-weight declarations of variable fonts** — the cached Google woff2s are full 100–900 variable files but were declared at one weight, pinning Chrome to the default instance and synthesizing every other weight; fixed by `font-weight: 100 900` declarations, with a verified print-pipeline constraint: all faces of one family must declare IDENTICAL weight descriptors or Chrome's print snapshot drops the base face. **(b) Latin subsets lack the symbols** — coverage is now split honestly across companion subset files under the same family names with disjoint unicode-ranges: Albert Sans/Lexend `text=` subsets supply their native Δ ≈ ≤ ≥; → ↔ ′ come from an Inter subset aliased under both families (Inter is the body stack's first fallback — the sanctioned substitute). Noto Sans was tried first and silently shipped a ′-only file: **Google's `text=` subsetter echoes the requested unicode-range while omitting glyphs the font lacks** (base Noto Sans has no arrows), so subset files are verified by glyph-coverage probe and the generator throws on any missing font file. **(c) the decisive hidden one: Google Fonts `@import` pollution from inlined SVGs** — `type-samples.svg`/`type-scale.svg` carry a `<style>@import` for standalone viewing; the PDF generator inlines SVGs, an inlined SVG's `<style>` joins the *document* stylesheet, and the imported single-weight latin-subset faces then win font selection at their exact weights and evict every non-latin glyph from the family (found by canary-paragraph auto-bisection of the rendered HTML: a paragraph whose Δ resolved in isolation fell back the moment the typography specimen entered the document). The generator now strips `@import`-bearing `<style>` blocks when inlining. Also in the wave: `orphans/widows: 3` and table pagination (`page-break-inside: auto`, `thead` as `table-header-group`, per-row `avoid`) for the orphan page gaps — 40 → 39 pages; and a `PDF_DEBUG_HTML` env affordance preserving the exact printed HTML for forensics. **Codex critic round 1 (revise) — four findings, all implemented:** JetBrains Mono moved to its variable 100–800 file with identical descriptors on both mono faces (the guide's four 600-weight code contexts — code spans inside a heading and three strong runs — now render a real 600 instance instead of synthetic bold); the SVG `@import` strip re-scoped per `<style>` block and made case-insensitive (the old regex could span from a benign style block across intervening SVG content into an importing one); a failed SVG inline now THROWS instead of silently reverting to the `<img>` path (which renders isolated with host fonts); and the generator gained a **post-print output gate** — it parses the produced PDF's font objects and fails the build unless every BaseFont/FontName/FontFamily EXACTLY matches a brand face (anchored family + instance-suffix pattern — a hostile `InterloperHost` cannot ride `Inter`), fails loud if zero font records are found (scanner/layout mismatch must not pass open), and glyph-bounds the dual-role families via their decoded ToUnicode CMaps: Inter faces may carry only ′ → ↔, and the platform colour-emoji face only 🎉 — so a HOST-installed Inter or an emoji face smuggling text glyphs also fails. The accepted emoji face's NAME is platform-dependent by design (Segoe UI Emoji on Windows, Noto Color Emoji on Linux, Apple Color Emoji on macOS — all three allowed, all identically glyph-bounded): the gate's first CI run proved this by correctly rejecting the Linux runner's Noto Color Emoji until the platform set was encoded, which is the gate catching real cross-host variance on its first contact with a second platform. Because Chrome's PDF splits identity and content across objects (descriptors carry names but no CMap; font objects carry the CMap but no name), the bound is applied through the font→descriptor object graph with identity resolved BEFORE any CMap look-up, and a bounded face with a missing, empty, or undecodable CMap fails closed (a stripped CMap cannot bypass the bound — byte-level mutant tests verify both paths). This closes the input-side blind spot (a readable-but-deficient subset passes every input check; only the output proves determinism). Negative-tested: the gate flags the pre-wave PDF's SegoeUI/SegoeUI-Semibold/Arial-BoldMT/Consolas, 13/13 name-anchoring cases behave, the live run reports 4 glyph-bounded faces checked, and a tightened-bounds mutation correctly flags the real Inter arrows (proving the bounds path executes); its first live run also caught Chrome's hyphenated variable-instance names (`JetBrains-Mono-Medium`) until the allowlist covered them. **Verified end state:** embedded fonts are exactly Albert Sans 400/600/700, Lexend 400/500/600, JetBrains Mono 400/600, Inter 400/600 (arrows), plus Segoe UI Emoji ×1 — the guide's three 🎉 anti-example occurrences, correctly host-rendered (colour emoji); font gate green.
